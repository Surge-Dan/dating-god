# 单场引擎

## 资源分工

| 资源 | 职责 |
| --- | --- |
| `assets/content.js` | 已发布角色、场景节点、条件变化、禁忌标签和对白 |
| `assets/engine.js` | 匹配、场次状态、事件、暂停、同意、结束、快照重演 |
| `assets/app.js` | 表单、现场操作、回看选择和本地下载 |
| `assets/report.js` | 证据呈现、确认语句过滤、HTML 和 SVG 序列化 |

## 匹配与回合

- 硬条件先于软偏好。只有成年确认、角色视角兼容、对象呈现与选定场景都可用才进入候选集。暂不指定与都可以都保留可用呈现，前者在便笺隐藏性别，后者显示。禁忌通过内容审核与节点标签过滤。优先偏好、后续偏好和兴趣逐级排序，同分用本场随机种子。
- 页面只提交可见动作及预期回合。引擎先验状态和动作，再确定角色回应、地点、剧情时间和条件变化。拒绝的提议从动作列表移除。角色可提出不同的可行安排，角色的邀请要等用户单独确认才成为双方约定。
- 结束即停止本场动作，暂停冻结剧情时间。每个有效动作保存反应、可见变化和前置快照。重演从该回合前复制状态，只更改新的分支，原场继续作为独立证据。早退可以没有任何可引用事件。
- 世界时间只按场内有效动作推进。浏览器等待、提示和暂停不会消耗角色时间。关页、重载和重置均从新状态开始。

## 扩展内容

- 角色的性别和称呼用于呈现。日程、表达主动性和回应风格来自独立的角色卡。每张卡补齐公开便笺、兼容组合、限制和至少一条可验证的独特策略。
- 发布组合必须经过边界、角色口吻、时间和完整路径校对。给每个新场景至少一条平顺结束和一条可选变化路径。只在已发生事实支持时回收共同回忆。
- 当前网页采用预写的动作和对白。原设计的自由输入、定制角色、模型回合及跨宿主同一在线入口需要另一个正式接入阶段。
