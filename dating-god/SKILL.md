# Dating 之神 · 见面之后

## 启动一场

1. 用户明确要启动时，定位本 Skill 的 [约会首页](assets/index.html)，用可用的宿主导航能力打开本地网页。只有确认已经打开时才说「已打开」。桌面 Windows 如果没有专用导航工具，且本机能打开用户请求的网页，用 PowerShell 的 `Invoke-Item -LiteralPath` 打开该文件。只执行固定入口，不拼接用户输入。
2. 同一条回复提供指向该文件的可点击入口。宿主明确拒绝导航或缺少导航能力时，直接给入口，说明需要在能访问 Skill 目录的浏览器里手动打开。只确认用法或想了解功能时，先回答问题。
3. 让网页处理成年确认、地点、对象偏好、边界、约会和回看。保持 `assets/` 整个目录一起可用。网页无需服务端、API 密钥或联网。在共享机器、无法访问本地文件的聊天端或移动端，明确说明打开条件。
4. 约会通过选择动作推进。它包含书店咖啡首见、朋友第一次单独见面、第二次约会做陶艺。网页内所有角色是虚构成年人，页面里的提示、暂停和重演都属于当前这一场。

## 完成与退出

- 成年确认由页面完成。已明确未成年时不启动成人模拟。遇到用户正在经历现实危险、胁迫或即时伤害风险时，先按宿主的安全流程回应现实情况。
- 用户在网页里自由决定是否看回看、下载脱敏 HTML 或下载确认过的 Dating 卡。向用户解释报告时，只使用用户主动提供的文件或材料，按 [回看与分享规则](references/review.md) 区分现场记录、虚构角色、解释和本人确认。
- 每次启动、重置或重新加载都是新场。无需收集或记住用户档案。别把上次的故事、身份或约定自动带入这次。用户明确取消就停止启动或说明可关闭页面。

## 维护与排查

- 修改匹配、状态、场景或重演时，先读 [约会引擎约定](references/engine.md)。内容源在 `assets/content.js`，验证前不要把草稿角色或场景加进匹配清单。
- 修改复盘证据、隐私和文件交付时，先读 [回看与分享规则](references/review.md)。网页代码无法可靠地识别自填文字里所有真实身份信息，确认与预览是用户控制分享范围的入口。
